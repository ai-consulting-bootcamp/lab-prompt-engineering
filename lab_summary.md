I diagnosed three failing chatbot prompts (sentiment, product description, data extraction) by running each 5, 10 and 15 times at temperature 0.7. Consistency got worse with more runs, and new failure patterns only appeared after 10+ runs. The v1 prompts said what to do but not how the answer should look, so the model invented sentiment categories (20% consistency), wrote ~1,900-character descriptions with hallucinated brands and specs, and returned markdown instead of JSON (0/15 valid). Explicit labels, output formats and constraints (v2) brought sentiment to 100% and extraction to 15/15 valid JSON. Few-shot examples and Chain-of-Thought (v3) kept these results and handled new cases correctly, including sarcasm and missing data (null instead of invented values). Product length was the hardest: a word-count rule had no effect, a matched few-shot example raised it to 6/15, and a code retry to 11/15 at about 2.4× the API cost. Testing new products showed why: the fewer facts a product has, the more “do not invent” conflicts with “about 60 words” (3 facts: 5/5, 1 fact: 2/5). My main lessons are that format consistency and correctness are different measures, that models follow examples better than numbers, and that I should check my measuring code before blaming the model. Next time I would use fixed value lists for free-text fields and scale the length target to the input.
